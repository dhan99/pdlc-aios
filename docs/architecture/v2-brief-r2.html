r2 revision log (critical review, Aug 2026). Eight changes folded in: (1) the stack is now phase-entry-gated — Gates 0–2 run on Claude Code + Actions + LangSmith + Postgres alone; LangGraph enters at Gate 3, Temporal only on demonstrated need; (2) the traceability spine is Postgres-first, promoted to Neo4j only if traversal queries demand it, and degrades to warn-and-queue (24h grace) instead of hard fail-closed; (3) critics and the LLM judge are cross-family via LiteLLM — same-family generator/grader pairs share blind spots; (4) evals run report-only until seeded (~50+ labeled examples per dataset) before they gate; (5) uniform gates replaced by risk-tiered gating with SLAs; (6) a per-feature cost model is published at Gate 1 and gates Gate-2 entry; (7) EARS scoped to functional ACs — NFRs become fitness functions, the rest carries an explicit not-machine-checkable flag; (8) human baseline capture, SDK pinning, MCP supply-chain attestation, and a Gate-3 de-scope fallback added to the roadmap.

1 · Stack decision & discipline scope

V2 activates a subset of the 45 AIOS disciplines (the "activation priority" list plus their supports). Each in-scope discipline gets exactly one owning technology. Out of scope for this workload: Fine-Tuning & PEFT, Edge & On-Device AI, Multimodal Interface Eng, Synthetic Data Eng (except optional eval-corpus augmentation), Semantic Layer/NL2SQL, Salesforce horizontal.

Phase-entry gating (r2): owning a discipline does not mean deploying its technology on day one. The V1 anti-pattern list includes framework-first architecture — so the stack enters in waves: Gates 0–2 = Claude Code + GitHub Actions + LangSmith + Postgres only; Gate 3 adds LangGraph (durable RDR gates are its first real requirement) and the spine CI check; Temporal, Neo4j, and dedicated microVM fleets enter only when a measured need appears (multi-week workflows, traversal-heavy queries, sandbox scale).

2A · End-to-end process flow

The complete flow from intake brief to operated production change: twelve agents, four platform-enforced human gates (G1–G4), EARS as the requirements interlingua, the LangSmith flywheel, the Postgres traceability spine, and ADAF phase gates governing the rollout itself. Long dashed orange lines are human-gate interventions; solid lines are automated flow.

Reading order: brief → agents 1–4 across the RDR plane (G1, G2 gating promotion) → spec artifacts → per-task dispatch into the sandboxed inner loop (agents 5–6) → draft PR → required checks and G3 human merge → canary → propose-only ops (agent 10, G4). The flywheel (bottom-left) closes the loop: every failure and reviewer correction becomes an eval case that gates future agent changes. The spine (right rail) makes every merge traceable to an approved requirement.

Rule of thumb: if the step is a pipeline stage with a gate, it's a LangGraph node. If the step touches the repo, it's a Claude Code session dispatched by a node. Never orchestrate multi-hour repo work inside a single LangGraph node, and never encode pipeline governance inside a Claude Code prompt.

4.1 State schema

from typing import TypedDict, Literal
from pydantic import BaseModel

class EARSRequirement(BaseModel):
    id: str                      # "FEAT-123-R4" — stable, global; the traceability currency
    pattern: Literal["ubiquitous","event","state","unwanted","optional"]
    text: str                    # must match its EARS template — validated, not hoped
    invest_score: dict[str, int] # I,N,V,E,S,T each 1-5
    source_story: str

class GateDecision(BaseModel):
    gate: str; approver: str; decision: str; comment: str; ts: str  # audit trail (L4)

class RDRState(TypedDict):
    feature_id: str
    brief: str
    open_questions: list[dict]        # [{q, answer|None, load_bearing}]
    stories: list[dict]
    requirements: list[EARSRequirement]
    design_md: str | None
    adrs: list[str]
    critic_findings: list[dict]       # threat + consistency, merged
    tasks: list[dict]                 # each: {id, desc, req_ids[], est}
    gate_log: list[GateDecision]

4.2 Nodes — clarify, gates, formalize, critics

from langgraph.graph import StateGraph, START, END
from langgraph.types import interrupt, Command
from langchain_anthropic import ChatAnthropic

clarifier  = ChatAnthropic(model="claude-sonnet-5", max_tokens=4096)
formalizer = ChatAnthropic(model="claude-sonnet-5")
designer   = ChatAnthropic(model="claude-opus-5")      # frontier tier for architecture
critic_llm = init_chat_model(CRITIC_MODEL)             # r2: CROSS-FAMILY via LiteLLM —
# same-family generator/critic pairs share blind spots; route critics & judge to a
# different model family (config, not code — CRITIC_MODEL lives with the model pins)

def clarify(state: RDRState) -> dict:
    """Elicitation agent. Interrogates the brief; NEVER invents answers."""
    result = clarifier.with_structured_output(ClarifyOutput).invoke(
        CLARIFY_PROMPT.format(brief=state["brief"]))   # prompt = versioned asset, eval-gated
    return {"open_questions": result.questions, "stories": result.candidate_stories}

def pm_gate(state: RDRState) -> Command[Literal["clarify", "formalize"]]:
    """HUMAN GATE 1 — durable pause. Unresolved ambiguity blocks promotion."""
    unanswered = [q for q in state["open_questions"] if q["answer"] is None]
    if unanswered:
        answers = interrupt({                    # surfaces in Agent Inbox; graph sleeps
            "gate": "pm_clarification",
            "feature": state["feature_id"],
            "questions": unanswered,
        })                                       # resumes here — days later is fine
        merged = apply_answers(state["open_questions"], answers)
        if any(q["answer"] is None for q in merged):
            return Command(goto="clarify", update={"open_questions": merged})
    return Command(goto="formalize",
                   update={"gate_log": state["gate_log"] + [log_gate("pm", answers)]})

def formalize(state: RDRState) -> dict:
    reqs = formalizer.with_structured_output(list[EARSRequirement]).invoke(
        EARS_PROMPT.format(stories=state["stories"], answers=state["open_questions"]))
    for r in reqs:
        assert ears_regex_valid(r)               # deterministic template validation
    return {"requirements": [slice_if_oversized(r) for r in reqs]}

4.3 Critic fan-out and the architect gate

def design(state: RDRState) -> dict:
    out = designer.invoke(DESIGN_PROMPT.format(
        requirements=state["requirements"], constraints=load_constraints()))
    return {"design_md": out.design_md, "adrs": out.adrs}   # ADRs: terse, agent-optimized

def threat_critic(state: RDRState) -> dict:      # runs in PARALLEL with consistency_critic
    f = critic_llm.invoke(STRIDE_PROMPT.format(design=state["design_md"]))
    return {"critic_findings": f.findings}       # reducer merges both critics' findings

def consistency_critic(state: RDRState) -> dict:
    f = critic_llm.invoke(COVERAGE_PROMPT.format(
        requirements=state["requirements"], design=state["design_md"]))
    return {"critic_findings": f.orphans_and_gaps}

def architect_gate(state: RDRState) -> Command[Literal["design", "plan_tasks"]]:
    """HUMAN GATE 2 — architect sees design + BOTH critics' findings + trace link."""
    d = interrupt({"gate": "architect_review", "design": state["design_md"],
                   "findings": state["critic_findings"],
                   "trace_url": current_run_url()})          # L1 transparency
    if d["decision"] == "revise":
        return Command(goto="design", update={"brief_addendum": d["comment"]})
    return Command(goto="plan_tasks", update={"gate_log": [...]})

  • write_artifacts commits specs/FEAT-123/{requirements,design,tasks}.md to a branch via the GitHub MCP server and registers rows/links in the Postgres spine (§7).
  • Risk-tiered gating (r2), not uniform gates: a tier matrix replaces the binary full/delta split. Tier 0 (docs, config, two-line fixes): delta graph, no G1/G2. Tier 1 (bounded feature work): G1 only, G2 waived if the consistency critic is clean. Tier 2 (new interfaces, data model, security surface): full G1+G2. Tier 3 (irreversible/regulated): full gates + explicit sign-off. Tiering is assigned at intake, auditable, and gates carry SLAs (< 1 business day) with escalation — the METR lesson is that review capacity is the constraint; gates must be spent where risk lives.
  • EARS scope (r2): EARS is mandatory for functional acceptance criteria only. NFRs (latency, cost, availability) are captured as measurable fitness functions with budgets, verified in CI/canary — not shoehorned into WHEN/SHALL. Anything not machine-checkable carries an explicit untestable: reason flag so it is consciously accepted, never silently dropped.
  • Every prompt (CLARIFY_PROMPT, EARS_PROMPT…) is a versioned file; changing one triggers the eval gate (§8).

5 · Inner loop — Claude Code dispatched per task

5.1 Dispatch from LangGraph (Agent SDK)

from claude_agent_sdk import query, ClaudeAgentOptions

async def implement_task(task: dict, feature_id: str) -> dict:
    """One bounded session per task — V1 compounding-error rule. Runs INSIDE the sandbox."""
    opts = ClaudeAgentOptions(
        cwd=f"/sandbox/repo",
        permission_mode="acceptEdits",
        allowed_tools=["Read","Edit","Write","Bash","Grep","Glob"],
        max_turns=40,                                   # runaway guard
        model="claude-sonnet-5",
        system_prompt_append=HANDOFF_CONTRACT.format(   # curated context, not the whole spec
            task=task,
            requirements=load_reqs(task["req_ids"]),    # only linked EARS requirements
            design_slice=slice_design(feature_id, task) # only relevant sections + ADRs
        ))
    async for msg in query(
        prompt=f"""Task {task['id']}. FIRST write failing tests encoding each EARS
        criterion verbatim (one test per criterion, named test_{{req_id}}).
        THEN implement until green. Never modify the tests after writing them.
        Commit with trailer: Implements: {','.join(task['req_ids'])}""",
        options=opts):
        record_to_langsmith(msg)                        # unified tracing (§9)
    return session_summary(msg)

5.2 Actor–critic round (never self-grading)

After implementation, a fresh session — new context, reviewer subagent, read-only tools — grades against an explicit rubric. Findings loop back (max 3–5 rounds) before the PR opens:

# .claude/agents/code-reviewer.md
---
name: code-reviewer
description: Reviews a diff against linked EARS requirements. Read-only.
tools: Read, Grep, Glob, Bash(git diff:*)
model: opus
---
You did not write this code. Review the diff against: (1) each EARS criterion —
met/not-met with evidence; (2) security (OWASP top-10, secrets, injection);
(3) repo conventions per CLAUDE.md; (4) test adequacy — do tests genuinely
encode the criteria or merely mirror the implementation? Findings only. No fixes.

6 · Outer loop — CI, review, deployment, ops

  • Every PR: anthropics/claude-code-action@v1 reviews the diff against the EARS requirements in its Implements: trailer (posts inline comments, never approves) + claude-code-security-review scan. Required status checks: tests · security · eval gate (§8) · traceability check (§7) · OPA policy check.
  • OPA merge policy (Policy-as-Code, L4): Rego rules evaluated in CI — deny merge if: PR author is an agent identity AND any approver is an agent identity; no Implements: trailer; eval-gate status missing; diff touches protected paths without a human commit.
  • CI-failure autofix: red main triggers a headless session that opens a proposal PR on agent/ci-fix/*. Never pushes to main.
  • Deployment verification (SRE for AI, L5): agent-authored changes deploy behind canary gates (error rate, latency, burn-rate SLO) with automated rollback — standard progressive delivery (Argo Rollouts / Harness), agent-agnostic by design.
  • Ops agents: incident-investigation as a LangGraph graph — parallel hypothesis nodes over observability MCP tools, synthesis node drafts the RCA + remediation proposal, interrupt() for approval. Propose-only, always: the industry consensus line (Datadog/PagerDuty pattern).

7 · Traceability spine — Postgres-first (r2)

r2 change: the spine's logical model is a graph; its storage is Postgres — the same instance already holding checkpoints, vectors and Store. At PDLC scale these are joins, not deep traversals: one less tier-0 system, one backup story, one identity. Promote to Neo4j only when a measured need appears (multi-hop impact analysis across hundreds of features).

-- CI traceability check:
SELECT r.id AS orphan
FROM   requirements r
WHERE  r.feature_id = :feature AND r.status = 'approved'
AND    (NOT EXISTS (SELECT 1 FROM implements i WHERE i.req_id = r.id)
     OR NOT EXISTS (SELECT 1 FROM verifies v  WHERE v.req_id = r.id));
-- any rows → status check fails
  • Writers: the RDR graph registers requirements/design/tasks at write_artifacts; a webhook-driven steward ingests PR merges and test files (parsing Implements: trailers and test_<req_id> names).
  • Drift detection: nightly steward job diffs merged code vs approved specs; drafts link updates and drift flags into a review queue — AI drafts, humans verify a sample (~10% random + every low-confidence link), not every link (r2 — verify-everything doesn't scale).
  • Degradation (r2): spine unavailable → traceability check reports warn-and-queue with a 24-hour grace window (merges proceed, links back-filled and verified on recovery); hard fail-closed applies only to Tier-3 changes. A secondary datastore must not be a tier-0 merge dependency.
  • The spine is exposed to agents via a read-only MCP server; writes go only through the steward service identity.

8 · Eval engineering — LangSmith as the regression gate

Cold-start rule (r2): a gate with an empty dataset is theater. Evals run report-only through ADAF Gate 1 while datasets are seeded from three sources: historical tickets/PRs (real requirements with known outcomes), synthetic cases (planted ambiguities, planted bugs), and early reviewer corrections via annotation queues. Enforcement switches on per dataset once it holds ~50+ labeled examples and a measured baseline — and only after the judge itself is validated against human labels (agreement ≥ agreed threshold).

8.3 The flywheel (Feedback Loop Eng., L1 → Eval Eng., L4)

  1. Production failure or reviewer correction observed (gate rejection, PR comment, drift flag).
  2. The implicated LangSmith trace is sent to an annotation queue; a human labels expected behavior.
  3. Labeled trace is promoted into the relevant dataset — the failure can never silently recur.
  4. Weekly: review judge/human agreement on a sample; recalibrate rubrics (judges drift too).

9 · Observability — one trace plane across both runtimes

  • LangGraph side: LANGSMITH_TRACING=true — every node, LLM call, interrupt, and resume traced per thread; the feature's whole RDR history is one navigable tree.
  • Claude Code side: CLAUDE_CODE_ENABLE_TELEMETRY=1 + OTLP exporter → OTel Collector → LangSmith (OTLP ingest), tagged with feature_id/task_id/agent_session_id so coding sessions nest under their dispatching pipeline trace.
  • Correlation key discipline: feature_id is the thread ID, the spine partition key, the commit-trailer prefix, and the trace tag — one join key end to end.
  • Dashboards/alerts: gate latency (is review the bottleneck? — V1's METR warning, watched weekly) · acceptance rate per agent surface (honest range ~35–44%) · post-merge churn on agent commits · token cost per feature per node · eval score trends · DORA before/after.

10 · Governance & security consolidated

Platform-enforced invariants (all three enforcement points):
  1. No agent merges/approves its own work — GitHub ruleset (agent Apps excluded from approvers) + OPA CI check + branch protection.
  2. No agent grades its own output — critics are separate LangGraph nodes / fresh Claude sessions; spec-derived tests are the acceptance gate.
  3. Gates block, not warn — interrupt() halts the graph; hooks deny writes to gated artifacts; CI checks are required. (Scoped in r2: the traceability check alone degrades to warn-and-queue per §7 — human gates and eval/security checks never do.)
  4. Sandbox always — microVM/ephemeral runner, egress allowlist, agent/* write scope, no long-lived credentials.
  5. Irreversibility → human — money, deletion, prod config: PreToolUse deny + interrupt escalation.
  6. Every agent identity is real identity — one GitHub App per agent surface; every commit carries Agent-Session: + Implements: trailers.
  7. Eval gate on every agent-estate change — prompts, hooks, graph code, model pins are code.
  • Prompt-injection defense (Red-Teaming, L4): untrusted text (issue bodies, PR comments, vendor advisories) is never concatenated into privileged sessions — it enters via MCP tools that return it as data with provenance labels; promptfoo red-team suites run the injection corpus against clarify/review surfaces in CI; CI runners that read untrusted text hold no write credentials.
  • Data boundary (Privacy & Sovereignty, L4): model access via Bedrock/Vertex where residency demands; LangSmith self-hosted option inside the VPC; specs and traces never leave the identity boundary.
  • MCP supply chain (r2): MCP servers are themselves attack surface (tool poisoning, dependency compromise). Every MCP server in the estate carries an AIBOM/SBOM, a signed release (cosign + transparency log), and a version-pinned manifest; agents connect only to registry-listed, attested servers — the same attestation discipline applied to any other production dependency.
